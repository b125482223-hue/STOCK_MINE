# 每日更新排程

GitHub Actions 於台灣交易日執行下列更新與重試：

| 台灣時間 | 目的 |
| --- | --- |
| 11:47–17:17 | 每 30 分鐘錯峰排隊，吸收 GitHub 延遲並持續補抓盤後資料 |
| 14:50 | 抓取三大法人初步盤後資料 |
| 21:35、22:05 | 啟動信用監看；啟動後每 10 分鐘檢查，最多 12 次 |

若官方尚未提供當日上市資料，或當日休市，更新程式不會覆寫
`data/latest/market-dashboard.json`，網站會保留前一個交易日資料。

GitHub 免費排程沒有準時執行保證。2026-07-14 實際觀察到下午排程延遲超過兩小時，
因此排程改為從官方發布前提早排隊，並避開每小時整點的壅塞時段；多次重試只能降低漏抓風險，不能保證精準執行時間。
頁面上的資料完整度標籤表示更新批次的預定資料範圍；Actions 執行摘要會列出實際儀表板日期與來源問題。

信用交易、三大法人與期貨資料採獨立更新；其中一個來源尚未發布，不會阻擋其他已發布資料。
需要立即重試時，可從儀表板點選「手動更新 API」，再於 GitHub Actions 執行 `Run workflow`。
最近 100 次 API 呼叫結果保存在 `data/logs/api-call-history.json`。
每次紀錄包含觸發方式與 cron 字串，可用來比對原定排程和實際呼叫時間。

## 2026-07-16 排程檢討

### 現行規則

- 盤後主流程維持 13 個名義排程，負責指數、法人與期貨資料。
- 晚間信用交易改由獨立 watchdog 於 21:35、22:05 啟動；只要其中一次成功啟動，就會每 10 分鐘持續檢查。
- watchdog 每次探測只呼叫 TWSE 信用端點並寫入 API 紀錄；資料可用後才執行完整 9 API 建置。
